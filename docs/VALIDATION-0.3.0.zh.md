# 0.3.0 验证记录

验证日期：2026-10-19（Australia/Sydney）。目标宿主为 DeepSeek Harness 0.2.1-rc.2。

## 按需工具与上下文

生产插件通过实际 DSH ToolRuntime 挂载，并连接 Vercel 官方 MCP；测试创建两个独立 Agent scope，模拟两个聊天的工具可见性。

| 阶段 | A会话可见平台工具 | B会话可见平台工具 | 本插件工具定义JSON字符数 |
| --- | ---: | ---: | ---: |
| 全量目录对照 | 237 | 237 | 488,972 |
| 按需模式初始 | 0 | 0 | 2,986 |
| A加载项目查询后 | 1 | 0 | A为5,655 |

初始本插件定义减少99.39%。这是相同字段投影的JSON字符比较，不是token实测，也不是整个Harness上下文的降幅。其他插件仍有各自的工具定义成本。

搜索结果通过原生模型可见的 `content` 提供名称和短说明；测试据此取得名称，再经加载helper加载完整参数定义，最后调用原平台工具。定义不会同时复制进搜索结果和对话正文。

每个Agent的已加载集合最多4项，平台工具schema合计不超过32,000字符。每个会话使用独立限制；加载只调整本插件自己的限制，宿主和父Agent的限制继续生效。测试中的B会话额外禁用项目查询后，加载无法解除该禁用。A卸载后对应schema从其可见集合移除。

完整237项目录及其发现元数据仍保留在宿主。后台可用数与会话已加载数是不同指标。父Agent未加载的工具无法在子Agent中自行放开；需先由父层加载或调整其授权配置。

## 显式teamId读取

真实端点复现了默认项目查询成功、显式同归属teamId返回403的情况。生产原生工具执行路径中的兼容处理已成功返回7个项目，并保留已验证归属的结构化来源说明；没有执行平台写入。适用条件和保守失败边界见[显式范围兼容说明](PROJECT_SCOPE_COMPAT.zh.md)。

## 其他验证

长结果的模型文本默认呈现前12,000字符，并明确提示截断与续读偏移；原始MCP内容和结构化字段保留。真实ToolRuntime配合本地MCP fixture验证了分页拼接、跨Agent拒绝、Agent销毁及断线清理。缓存每Agent最多8项、合计100万字符，超限淘汰最旧项；单项超过100万字符或无Agent时不生成续读句柄，提示缩小查询。离线缓存测试覆盖字符预算、页边界和淘汰。

仍保留0.2.0的元数据、structuredContent、MCP错误、OAuth刷新、技能路径约束等测试。新测试还检查双Agent隔离、加载/卸载、模型可见搜索结果、宿主deny、审批链路、定义数量/字符预算及目录更新。

最终执行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm build`、`pnpm test` 均以0退出。全新临时DSH_HOME安装0.3.0 tarball后，真实Host与revisioned client bundle启动通过；停用路由404、重新启用200、卸载清理通过。包内含34个技能目录，安装产物的host/client哈希与最终build一致。

本机Desktop已从独立0.2.0包更新到同一0.3.0测试包；更新前备份配置，其他配置依赖保持一致，先前删除的GitHub插件保持缺席。本轮真实refresh成功。新版本的Desktop模型交互和上下文token显示仍需用户在新聊天中确认；尚未公开发布0.3.0。

真实生产探测和逐项离线检查分别记录在项目外handoff及被忽略的 `.upstream/validation-evidence/`；不上传OAuth凭据或原始项目数据。本版本不声称237项平台操作逐一执行通过，也未测试真实部署、写入或域名操作。
